# Second marketplace extraction source review

Reviewed 2026-10-12 for issue #16. The selected independent source is [Sharetribe's web-template](https://github.com/sharetribe/web-template/tree/1811b6a188a71e9ee6a41effed3139606cdd9f94), pinned to full commit `1811b6a188a71e9ee6a41effed3139606cdd9f94`. This is a bounded payment-module sample of a larger marketplace template, not a claim to have analyzed its whole application. Its [pinned LICENSE](https://github.com/sharetribe/web-template/blob/1811b6a188a71e9ee6a41effed3139606cdd9f94/LICENSE#L1-L13) states Apache-2.0 and copyright 2018 Sharetribe.

The useful source files are `server/api-util/lineItems.js`, `lineItemHelpers.js`, and `currency.js`. The first two have independent upstream tests in `lineItems.test.js` and `lineItemHelpers.test.js`. They implement customer/provider commissions, shipping and booking quantities, unlike BOID's creator/referrer fixture. Read dependencies include the Sharetribe SDK's Money type, decimal.js, dates helpers and moment; a source-only snapshot does not execute those dependencies.

## Scope and interpretation

An extractor miss means one of the reviewed facts above is present in this source slice but was not captured faithfully. A representational gap means BOID's current schema cannot express it (minimum commissions, signed line items, customer-added commission, shipping exclusion, or half-up rounding). Neither should be repaired silently by treating Sharetribe as BOID's fixed fee/referrer fixture.

Referral beneficiaries, referral eligibility, referrer rewards, Solana token mint/authority rules, escrow, and settlement execution are not established by this bounded source slice. Record those as unestablished in the slice, not proof that the whole Sharetribe application lacks them. No extraction score over these selected files is a general marketplace accuracy benchmark. Keep generation blocked until a reviewed model can represent the source semantics faithfully.
